## 拡張の仕組み

機能を増やすときに、土台を書き換えずに済む仕組みがあれば書く
（登録型・プラグイン型など）。なければ「なし」と書く。

新しく足すときの手順を、番号付きで具体的に残す。

## 認証の方針

認証がある場合のみ記入。ない場合は「なし」と書く。

| 対象 | ログイン方法 | 発行・管理 |
|------|-------------|-----------|
|      |             |           |

**自前の認証実装は避ける。** 既存のサービス・ライブラリに乗せる方針を基本とする。
強度を下げる判断をした場合は、その理由と運用でどう埋め合わせるかを書く。
